## T11 — 保存、生效与恢复闭环
复用现有 KV 后端，为一条专用偏好选最小命名空间；不新建数据库、EvidenceStore、通用 candidate 状态机。字段只保留 scope、固定参数值、可信来源、人工批准和批准时间、期限、撤销/暂停所需信息。
scope 必须从可信事件确定：平台实例/平台、bot 账号、发送者稳定 UID、会话，确认私聊。不要只凭 get_platform_name 的协议名或 private:UID 隔离账号；核对 get_platform_id/现有完整 identity 能力。缺失、冲突、群聊、合成任务或来源不可信时不生效。
捕获来源不得靠调用者随便填写 source ID 或把任意文本标注成已批准。人工入口应解析真实已有来源记录，或在真实入站时保存最小待核实请求引用；没有历史正文可核验时不得伪造补全。手动核实明确要求可以替代通用自然语言分类器，不添加 LLM Agent。不用宽松关键词命中自动批准、撤销或改状态；保留可用的明确操作入口。
批准成功后七天有效；同来源重复处理不新增、不延期，包括重启后、撤销后和到期后。持久化失败不得回报批准成功，不让失败状态影响注入。严格解码损坏/未知值，读取失败不注入。
只在真正最终请求的现有临时动态内容位置注入受控文本，一次且同 scope；不将自由文本当策略、不改核心 Persona。重复处理同请求不重复注入；撤销/到期后不能遗留旧请求块。
本次明确要求覆盖保存偏好；固定注入文本明确此优先级，不宣称模型输出具有强制保证。明确恢复默认可撤销；相反持续要求暂停旧偏好，等待人工处理。可使用简洁受控命令处理撤销/冲突，不假装通用语义识别已实现。
恢复是停止偏好覆盖，使用当时默认配置，不回写旧配置。
验收：候选未批准无效果；批准后可测请求改变；去重/到期/撤销/重启正确。
